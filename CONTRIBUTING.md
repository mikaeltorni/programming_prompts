# Contributing to programming_prompts

Thanks for improving this prompt, plugin, and skill content. Keep changes focused, explain user impact in the pull request, and update the README or canonical docs when commands, configuration, or supported integrations change.

## Before opening a pull request

- Read the repository README and any local agent instructions.
- Run the validation command from the README or workflow.
- Do not commit API keys, model weights, generated outputs, private telemetry, or credentials.
- Use descriptive commit messages and include reproduction steps for fixes.

## Documentation standard

New public behavior needs a copy-pasteable example and a troubleshooting note when failure is likely. Prefer precise capability and limitation statements over performance claims without receipts.
